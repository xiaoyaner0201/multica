按 `multica-engineering-delivery` 的风险触发器机械判定，命中以下各项，任一即
`HIGH_RISK`，Agent 不得自行降级：

| 触发器 | 命中事实 |
|---|---|
| authentication / 凭据 | `SendVerificationCode` 投递的是一次性登录码，**凭据本身就在被改写的 body 里**；模板渲染缺陷直接落在认证路径上 |
| 跨 tenant / workspace | `buildInvitationParams` 把 `inviterName` / `workspaceName` 从一个 workspace 投递给尚未认证的站外收件人 |
| notification / fan-out | 同一逻辑消息有三条 sink：SMTP relay (`sendSMTP`)、Resend API (`s.client.Emails.Send`)、DEV stdout (`fmt.Printf`)；subject 目前在 SMTP 与 Resend 两处**重复字面量** |
| 个人数据 / 不可逆 | 已发出的邮件不可撤回；渲染缺陷的 blast radius 是站外收件人 |

附加的不变量面（不单独构成触发器，但决定验证深度）：

- 现状是**两套不同的转义模型**：body 走 `html.EscapeString`，subject 走
  `sanitizeSubjectField`（剥控制字符 + 截断，**刻意不做 HTML 转义**，否则收件箱里会出现
  字面 `&lt;script&gt;`）。迁移到 `html/template` 会引入第三套自动转义模型，
  双重转义与转义丢失是对称的两个失败方向，二者都是 `INVARIANT_VIOLATION`。
- operator 提供的模板是**新增的、半可信输入面**，此前不存在。
