## 流程摩擦（本 Issue 是新版流程首次实跑，如实记录）

1. **记账正本引用的 `templates/` 子目录不存在。** `multica-ledger-bookkeeping` 正文多处写
   `templates/plan.md`、`templates/gate.md` 等，实际安装后这五个文件平铺在 skill 根目录
   （`plan.md` / `code.md` / `verification.md` / `review.md` / `gate.md`），没有 `templates/`
   一层。已在三张卡片正文中给出实际路径绕开，但正本行文应当修正，否则每个角色都要踩一次。

2. **卡片张数：Issue 正文写「四张卡片」，两份正本写「三张卡片」。** 父 Issue 的「本次运行的
   额外观察要求」一节描述新流程为「四张卡片 + 两道人工闸门」，而 Squad Instructions 与
   Agent Identity 均明确为「三张工作卡片：方案、实现、评审；两道闸门在父 Issue 上」。
   按正本执行（三张，实现与验证共用 stage 2 卡片、靠评论 mention 接力），在此报告该冲突。
   推测是「四个执行角色」与「三张卡片」在表述上被混同。

3. **单张卡片内实现「Pass 1 / Pass 2 必须是不同 Run」缺少机制。** 方法正本要求评审两遍分属
   不同 Run 且 Pass 1 不得接触方案与验证产物，但一张卡片默认只派一个 Run。当前唯一可用手段
   是让评审在冻结 Pass 1 产物后，在自己卡片上自 @ 触发第二个 Run。已写进 HD-54 正文，但这是
   绕路而非机制支持，且 Pass 1 的「盲」最终仍只能靠角色自律（账本与代码在同一个 checkout 里，
   `planner/` 与 `qa/` 目录对它是物理可读的）。

4. **`multica repo checkout` 会先落到一个自动生成的 agent 分支**（本次是
   `agent/agent/748e803bd703`），需要手工再切到 intake 定死的分支。下游角色用
   `--ref feature/email-template-customization` 检出可直接命中，但该分支必须已经 push——
   这也是我在建卡片时把三张卡片都先置 `backlog`、等账本 push 完成后才提升 HD-52 的原因。
   若按「建卡即 `todo`」的直觉操作，规划会在分支存在之前开工。

5. **fork 的 `main` 落后 upstream 16 个提交**，没有任何机制提示这一点。BASE 选错会让
   Publication 阶段的 production-equivalence 比对凭空多出 16 个提交的差异。这一步目前完全
   依赖 intake 时人工去 `git rev-list --left-right --count`。
