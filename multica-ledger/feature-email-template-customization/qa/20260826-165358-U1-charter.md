## 从代码树重建的行为面

```text
EMAIL_TEMPLATE_DIR
  → NewEmailService
  → 四个固定文件名的读取 / 解析 / 零值诊断
  → EmailService 上四个可独立为 nil 的只读 template 指针

HTTP 验证码请求
  → handler/auth.go 产生、持久化 code
  → SendVerificationCode
  → DEV 日志旁路，或 Subject/HTML 独立渲染与单组件回落
  → SMTP DATA / Resend SendEmailRequest
  → 收件人可见主题与 HTML

工作区邀请
  → handler/invitation.go 异步 goroutine
  → SendInvitationEmail
  → FRONTEND_ORIGIN + invitationID 派生 InviteURL
  → Subject/HTML 独立渲染与单组件回落
  → SMTP DATA / Resend SendEmailRequest
  → 收件人可见主题与 HTML
```

受影响的主体/状态：自建部署管理员可控文件；验证码收件人持有敏感 code；邀请人和 workspace 名可能是不可信字符串；邮件收件人只看最终传输载荷；SMTP/Resend 是外部传输边界；并发邀请 goroutine 会共享 template 对象。

## 最危险的反例

1. 带验证码的模板在 Execute 失败后，告警把 data 或部分渲染结果打入日志，邮件虽回落正常但敏感值多出一个 sink。
2. 自定义 Subject 的 CR/LF/非 ASCII control 或 MIME 编码膨胀绕过清洗，在 SMTP DATA 中形成第二个头或超过 998 octet。
3. 共享 template 并发 Execute 将 A 的 code/body 与 B 的 recipient 拼成一封信。
